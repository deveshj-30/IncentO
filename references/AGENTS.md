# Repository Guidelines

This repository is at its initial setup stage. It currently contains `reference/HackwithHyderabad 3.0 Problem Statament.pdf`, the supplied problem statement. Consult this document before defining requirements or implementing features.

No source, test, or asset directories exist yet. When introducing application code, group related modules together and document the chosen layout here. Keep reference materials in `reference/` and generated output separate from source files.

## Build, Test, and Development Commands

No build system, dependency manifest, or development scripts are configured. There are currently no application commands to run.

When adding a technology stack, provide reproducible commands for dependency installation, local development, production builds, linting, and tests. Record the required runtime versions and commands in a root `README.md`; update this guide accordingly.

## Coding Style & Naming Conventions

No language-specific style or formatter is established. Follow the conventions of the selected language, use consistent indentation within each file, and choose descriptive names for files, functions, and modules. Configure an appropriate formatter and linter alongside the first implementation.

## Testing Guidelines

No test framework or coverage threshold is configured. Add automated tests with the first executable features, including expected behavior and meaningful failure cases. Adopt the selected framework's test naming conventions and document how contributors run the suite.

## Commit & Pull Request Guidelines

The repository has no commits, so no commit-message convention exists. Use concise, imperative summaries, such as `Add initial application scaffold`, and keep commits focused.

Pull requests should explain the change, link relevant issues, and state validation performed or why validation was unavailable. Include screenshots for visible interface changes.

## Security & Configuration

Never commit credentials, API keys, or local environment files. When configuration is introduced, provide an example file with placeholder values and ignore private configuration and generated artifacts.

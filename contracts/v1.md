# IncentiveTrap Contracts v1 — Slice A (proposed, not yet frozen)

Shapes are defined in `backend/app/core/schemas.py` and exported to `contracts/openapi.json` and `contracts/schemas/*.json`. This file records semantics only. Never hand-edit generated files. Slice A is frozen at the commit that merges it after review by P1, P3 and P4; after that, changes are additive only. Slice B (dataset, incident, outcome shapes and endpoints) follows by G2.

## Conventions

- IDs are stable strings (`policy_id`, `customer_id`, `deal_id`, `ticket_id`, `incident_id`, `run_id`); never join on display names. `run_id` is the investigation ID.
- Timestamps are timezone-aware and serialized in UTC (`...Z`). Every analysis and recall uses an `as_of` cutoff and event time; future events must not leak.
- Money is `{amount_minor, currency}` (integer minor units, ISO code). Rates, discounts and interval bounds are fractions 0–1; a gap is a signed fraction (0.15 = 15 percentage points). Missing values are `null`, never 0.
- Unknown request fields are rejected (`extra="forbid"`).

## Metrics and statuses

`MetricName`: `discount`, `complaint_30d`, `cancel_30d` (also the token prefixes, e.g. `{{m:cancel_30d.gap}}`). Token fields: `month_end_value`, `other_value`, `gap`, `gap_lower`, `gap_upper`, `month_end_n`, `other_n`, `pre_policy_gap`, `status`. Constant tokens: `{{t:gap_threshold}}`, `{{t:baseline_margin}}`, `{{t:min_group_size}}`, `{{t:month_end_days}}`.
`MetricStatus`: `flagged`, `watch`, `no_signal`, `insufficient_data` (rules in `implementation_plan.md`). `AnalysisResult.flagged` is true only if at least one metric is `flagged` and at least two distinct customers corroborate it.

## Explanation rules the contract relies on

- Text fields in `Explanation` are resolved for display; `template_text` keeps tokenized originals for audit.
- `explanation_source` is `reflect` or `template` (deterministic fallback, with `validation_error_codes`).
- `memory_status` is `live`, `unavailable` or `fixture`; a stub or recording is never `live`.
- `Recommendation.action_type` is one of `adjust_policy`, `pilot_guardrail`, `revert_change`, `collect_more_data`, `no_action`. `success_metric` and `guardrail` are proposed targets, not calculated values. `history_influence` lists `RecalledMemory.id`s; empty when memory is off. No numeric confidence score exists.
- `Evidence.excerpt` is display-only untrusted customer text and is never sent to a model.

## Errors

Every error body is `{code, message, request_id, details[]}`. Codes: `validation_error` (422), `not_found` (404), `as_of_before_memory` (409), `retention_pending` (409), `idempotency_conflict` (409), `not_implemented` (501), `internal_error` (500). The `x-request-id` response header repeats `request_id`.

## Slice A endpoints (stubs until Phase 2)

`GET /api/health`, `POST /api/investigations` (returns 501 until Phase 3), `GET /api/investigations`, `GET /api/investigations/{run_id}`. Remaining endpoints from the plan arrive with Slice B.
